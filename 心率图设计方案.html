心率模拟 · 计算公式与心率图设计

目标：根据轨迹自带的速度 + 坡度（再叠加海拔），反推一条合理的心率曲线，并把这条心率曲线做成视频里的动态图表。 公式不是医学测量，是运动生理学模型可信的模拟：ACSM 徒步能耗方程 → 心率储备（Karvonen）→ 一阶惯性响应。 下面所有曲线都用项目里的真实轨迹（test / dog / cat.kml）跑出来，可直接对比观感。

一、计算公式 5 步链条

输入只有轨迹已有的东西：速度（KML 逐点 m/s，缺失时用位移/时间差回退）、坡度（沿用项目里的 compute_slope_pct，±3 点窗口、±60% 裁剪）、海拔（15 点平滑序列）、时间戳（真实间隔）。 另外 3 个人体参数：年龄、静息心率、VO2max。
STEP 1 · 输入归一
S = v × 60 // 速度 m/min
G = clamp(slope% / 100, -0.15, +0.35) // 坡度小数
速度先做 ±3 点均值平滑，剔除 GPS 抖动；坡度下限 −15%（再陡的下坡也不再降低能耗），上限 +35%。
STEP 2 · 代谢需求（ACSM 徒步方程）
VO₂ = 3.5 + 0.1·S + 1.8·S·G // ml/kg/min
下坡（G<0）改用 1.8·S·G×0.6
ACSM 徒步/跑步能耗标准式：平地每公斤每米耗氧 0.1，坡度每 +1% 追加 1.8。下坡取 0.6 衰减，避免「 downhill 白送」的失真。
STEP 3 · 心率储备映射（Karvonen + 低强度凸性）
HRmax = 208 − 0.7·age // Tanaka
%VO₂R = (VO₂ − 3.5) / (VO₂max − 3.5)
HR_ss = HRrest + %VO₂R0.85 × (HRmax − HRrest)
0.85 次方是低强度段的凸性校正：真实心率在热身区抬升比线性更快，没有它，4 km/h 平地会只有 83 bpm，偏高估舒适度。
STEP 4 · 一阶惯性（上升快 / 恢复慢）
HRi = HRi−1 + (HR_ss,i − HRi−1)·(1 − e−Δt/τ)
τ = τ_up 40s（上升） / τ_down 100s（恢复）
心率永远不会瞬移。上坡约 30~40s 爬到稳态，歇下来要 1.5~3 分钟才回落——这正好让「突然上坡」、「山顶打卡停顿」在图上自然可读。
STEP 5 · 收尾：平滑 + 夹逼 + 可选海拔
// 9 点滑动均值，然后
HR ≤ 0.96·HRmax
HR ×= 1 + 0.04·max(0, alt − 1500)/1000 // 默认关闭
海拔项默认关（0），需要时可开：1500m 以上每升高 1000m 心率约 +4%。
STEP 6 · 区间判定（画图用）
Z = HR / HRmax → 5 档区间着色
同一条曲线，颜色就直接表达强度：不用额外解释，观众一眼知道「这段很拼」。

五、每个方案怎么读 / 什么时候用

方案 A · 心率剖面卡
整条路线心率曲线 + 5 条区间底带 + 已走段区间着色 + 当前位置光点/虚线，左上角实时 bpm 与区间名、右上平均/峰值、底部里程。 结构与现有「海拔一览图」完全同构（同一套深色卡 + 白曲线 + 暖色进度），放在一起不会打架。
适合：主画面、全程复盘；“为什么这里累”一眼能看出来。
方案 B · 心率流带
190px 宽的竖向流带：每根柱子 = 一小段轨迹，高度=心率、颜色=区间；右侧大字当前值 + 区间胶囊 + 坡度/速度小字。 适合：620×1080 这种窄画布，或者放在地图下方当第二信息条；信息密度高但不占地方。
方案 C · 模拟心电卡
滚动心电波形（P-QRS-T 合成波，节律跟着当前心率加快/变慢）+ 大号 bpm + 底部区间标尺游标。 波形是装饰性合成，不是医学信号——但动态感最强。 适合：Vlog 人设、片头/片尾特写，或单独做一个小 HUD。
方案 D · 极简心率条
一条 360×36 的胶囊：爱心 + 4px 高的区间色带 + 当前数值。只占 1 行高度，可以贴着地图/数据面板放。 适合：地图导航旁边、画面底部字幕条上方；不抢地图视线。
共同点：未走 = 12% 白压暗，已走 = 区间色；当前位置统一白环光点 + 竖向虚线；字体用微软雅黑，字号/位置/透明度全部可调。 A 与现有海拔图同尺寸（默认 360×190 级），B/C/D 为新增紧凑尺寸。

六、代码怎么接（预估改动面）

完全沿用现有的「共享绘制函数 + GUI 与视频同像素」体系，不引入新依赖。
文件改动
renderer.py 新增模块级：心率区间常量/配色、hr_max_tanaka()、compute_heart_rate(points, speeds, slope_pct, params)、 hr_zone(hr)、四种图表的布局常量（与 GUI 预览共用）。
Renderer.__init__ 里一次算出 self.hr（时间域，与 fps/时长无关）；render_frame 里按 show_hr_chart 调用 _draw_hr_chart(img, d, idx_f)；静态底图（区间带/曲线/网格）走 _hr_cache，逐帧只叠标记。
app.py 新增 HRChartItem(QGraphicsRectItem)：paint 直接调同一绘制函数（ss=1），与视频端逐像素一致；
「外观与标注设置 → 海拔图 & 进度环」页新增分组「心率图表」：显示开关 / 样式下拉（A 剖面 / B 流带 / C 心电 / D 极简条）/ 大小 / 位置 / 年龄 / 静息心率 / VO2max / τ_up / τ_down / 海拔系数 / 预览播放（复用坡度仪的 QTimer 机制）。
.kmlproj 新增键：show_hr_chart、hr_chart_style、hr_chart_pos、hr_chart_w/h、 hr_age、hr_rest、hr_vo2max、hr_tau_up、hr_tau_down、hr_alt_k、hr_zone_colors（可选）。旧工程 getattr 兜底。
性能 底图缓存后，单帧成本 ≈ 一次 copy + 十几次线段/圆点绘制，与海拔图同一量级（远低于 PNG 编码）。 心率序列在 __init__ 里 O(n)，4000 点轨迹亚毫秒级。
与视频节奏的关系：心率按真实时间推进，改 fps / 时长只改变播放速度，心率数值不变； 分段模式下每段仍落在同一时间轴上，不会出现「每段都从 62 开始」的重置感（除非用户想要每段独立，那就加个开关）。

七、需要你拍板的 4 件事

1. 人体参数默认值：年龄 35 / 静息 62 / VO2max 42 是否贴近你本人？这决定曲线的整体高低。
2. 图表默认样式：A（剖面卡，信息全）还是 B（流带，紧凑）当默认？我倾向 A，和你现有海拔图并排。
3. 是否要“心率区间时长统计”：片尾/图角落显示 Z1~Z5 各占百分比（像 Strava 那样）。
4. 曲线是否要跟坡度联动配色：本文案里曲线颜色=心率区间；也可以改成曲线固定暖黄、只在背景标区间（更像海拔图）。
